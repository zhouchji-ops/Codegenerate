## 新实验流程

1. 从最新 main 建任务分支；复制 `experiments/TEMPLATE.md` 到 `experiments/expNNN_<benchmark>_<purpose>/README.md`。
2. 先写假设、对照、冻结的评测协议与预算，再添加配置和实现。正式执行命令在真实环境验证后才记为可复现。
3. 输出统一指向仓库外的 artifact root。服务器保存运行需要的代码和原始产物；研究分析文档维护在本地与 GitHub。
4. 文档记录外部产物索引、版本及核验后摘要。原始 JSON/CSV 即使很小也不是文档，不提交。
5. 运行检查、审阅 diff、精确暂存、提交、推送，再核对远端 SHA。

## 代码边界

`src/benchmarks/` 负责环境/任务/观测动作适配；`src/policies/` 负责模型调用；`src/generation/` 负责资产/场景代码生成与验证；`src/evaluation/` 负责协议和统计逻辑。仅在实际实现时创建模块，不预设所有 benchmark 共用同一种动作空间。

上游依赖用版本/提交固定，通过包装器或小型补丁实现差异。不上传上游权重、完整资产库或复制的第三方源码树。生成代码和生成结果分开：生成器属于仓库，生成网格/纹理属于外部产物。

## 检查范围

`check_repository.py --all` 审查全部工作文件（跳过 `.git`）；`--staged` 审查暂存内容而非工作区版本。脚本拒绝常见产物、未知扩展名、超过 1 MiB 的文件、二进制/NUL、明显私钥与令牌。它不是完整秘密检测器，仍必须人工审查配置、URLs、文档和原始结果混入情况。
